# Protocol sub-projects 2–6 and category coverage: one combined plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Follow the run rules in
> the handoff (`docs/superpowers/handoffs/2026-10-08-protocol-sp2-6.md`). Tasks give behaviour, interfaces and
> concrete test cases rather than literal code; the user asked for one plan and speed (2026-10-08). Implementers
> write the code test-first from these.

**Goal:** Finish the chemist's review of protocol creation (C3, C4, C6, C9, C10, C12–C15) and close the gaps in the
shipped category list, in one branch.

**Architecture:** Same layers as the create flow (DDD; railway Results; workspace scoping; orval types). Most changes
are additive. Two migrations (091 defining conditions, 092 references). Strain is a new naming slot stored in
`ontology_annotations`, so it needs no migration. Target requests reuse ProtCellar's existing `POST /api/v1/targets`
with the caller's own tokens; ProtCellar code is not changed.

**Source:** chemist's review C1–C16 in `docs/superpowers/reports/2026-10-08-chembl-naming-fit-test.md`; sub-project 1
spec `docs/superpowers/specs/2026-10-08-protocol-create-flow-design.md` (precedent for rules); the category gap list
below. This plan carries its own decisions instead of a separate spec per sub-project, by user ruling for speed.

## Global constraints

- Backend: Python 3.13, FastAPI, SQLAlchemy async, Alembic. Every use case is workspace-scoped (`require_same_workspace`)
  and role-guarded. Expected failures return `Failure(...)` (railway pattern), never raise. Read
  `docs/backend-code-guidelines.md` and `docs/patterns-and-conventions.md` before writing backend code.
- Frontend: Next.js 16, React 19, TanStack Query, react-hook-form + zod, shadcn/ui.
  - Never hand-roll an interface that mirrors a backend DTO: regenerate orval and import or alias the generated type.
  - No autosave on consequential actions. Never ask users for UUIDs. Admin UIs use proper controls, no JSON
    textareas. Every CSV import has a "Download Template" button.
- Units go through `canonical_unit`. Every unit a shipped form uses is already canonical
  (`canonical_unit(u) == u`, asserted by test).
- Names stay deterministic from facts; nothing generates names any other way. No LLM features (deferred by the user).
- Design general, not sample-tuned: rules come from structure (pattern, target type, workspace data), not from one
  lab's habits.
- Migrations: next numbers are **091** and **092**; dev DB is at `090_canonical_units_again`. Each migration has a
  downgrade and an integration test.
- Frozen records (closed campaigns, locked protocols) are never rewritten by migrations.

## Review focus (no task's tests reach these; the final reviewer checks them)

1. No change in this plan renames an existing protocol without the existing preview/confirm flow. That includes
   shipped pattern changes, home organisms and strain.
2. CSV import never invents an ontology id. An unresolved organism, cell line or target stays unresolved until a
   person picks it.
3. Reference links: only validated values become hrefs, built from fixed templates. No `javascript:` or `data:` URL can
   be stored or rendered.
4. Target requests use the requester's own tokens and workspace. Viewers can't create. Nothing is cached as a service
   identity.
5. Defining condition values and references follow protocol mutability: a draft is free; an active protocol is
   changed by correction with a reason (conditions) or audited update (references); a locked one is refused.
