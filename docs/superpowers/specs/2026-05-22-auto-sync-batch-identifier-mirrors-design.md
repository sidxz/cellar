# Auto-sync molecule synonyms → batch identifier mirrors

**Date:** 2026-05-22
**Status:** Approved (brainstorm)
**Branch target:** `prot-2`
**Builds on:** Batch identifiers (2026-05-21, migration 043) + bulk-import wizard (2026-05-21).

---

## Problem

Every molecule registered in Cellar produces 1..N batches whose `batch_number` is the molecule's registration number plus a sequential hyphenated suffix (`CC-036715` → `CC-036715-001`, `CC-036715-002`, …). Molecules also carry external lab synonyms (`SACC-0036913`, vendor codes, partner identifiers) in `molecule.identifiers`. Many external systems — partner spreadsheets, paper supplementaries, vendor catalogs — reference batches as `SACC-0036913-001` rather than `CC-036715-001`. Today those references fail to resolve because no mapping from `<synonym>-<suffix>` to a batch exists.

The chemist's mental model is symmetric: a molecule synonym implies a parallel batch synonym for every batch of that molecule, generated by appending the batch's hyphenated suffix to the synonym string. We want that mapping to materialize automatically so inbound lookups + bulk imports resolve through any synonym.

## Goals

- Every `MoleculeIdentifier` materializes one `BatchIdentifier` per existing batch of the molecule, with `identifier = f"{synonym}-{suffix}"`.
- Every new batch automatically materializes one mirror per existing molecule synonym.
- Removing a molecule synonym deletes its mirrors (cascade).
- Auto-mirrors and chemist-added batch identifiers coexist; conflicts skip with a warning, never block the parent action.
- Existing data (~50K molecules, ~50K batches from CDD imports) is backfilled in one shot.

## Non-goals

- **Rename propagation.** `Molecule.name` is set once at registration and never mutated by any public API (`UpdateMoleculeCommand` does not accept `name`). No code path exists to rename a synonym either — `RemoveIdentifier` + `AddIdentifier` is the only way to change one, and that flows through the create/delete fan-out paths.
- **Adoption of pre-existing manual mirrors.** A chemist-added `BatchIdentifier` whose string happens to match a future auto-mirror is left untouched (NULL FK preserved); a conflict warning is recorded and surfaced to the chemist. We do not retroactively rewrite source or assign ownership.
- **UI distinction on the Identifiers card.** Mirrors render identically to manual rows; the `source = "compound-syn"` label is the only differentiator for chemists who care to look.
- **Internal joins via aliases.** All internal FK lookups continue to use `Batch.id` / `Batch.batch_number`. Aliases are read-side artifacts for inbound lookups + bulk imports only.

## Locked design decisions

1. **Tracking mechanism: nullable FK.** New column `batch_identifiers.derived_from_molecule_identifier_id UUID REFERENCES molecule_identifiers(id) ON DELETE CASCADE`. NULL = chemist-added; non-NULL = auto-mirror. Cascade-delete is at the DB layer.
2. **Trigger placement: inline in use cases.** `AddIdentifier` (chemical_registration) and `CreateBatch` / `EnsureBatchExists` (inventory) each call a shared collaborator `SyncBatchIdentifierMirrors` (lives in `application/inventory/`). Synchronous, transactional with the parent action. `RemoveIdentifier` requires no code change — the DB cascade fires.
3. **Mirror identity:** `identifier_type = "custom"`, `source = "compound-syn"`, `derived_from_molecule_identifier_id = <parent>`, `registered_by = <actor of parent action>`.
4. **Suffix derivation:** `suffix = batch.batch_number.value.rsplit("-", 1)[-1]`. If the result is empty, identical to the full value (no dash present), or non-numeric, skip that batch and record `reason = "malformed_batch_number"`.
5. **Conflict UX: toast on action.** Both parent endpoints (`POST /molecules/{id}/identifiers` and `POST /batches`) return an enriched response carrying `mirror_summary = {created: N, skipped: [{batch_number, reason}]}`. The FE renders a Sonner toast: `"N batch mirrors created"` or `"N created · M skipped"` with a Details action listing the skipped rows.
6. **Backfill: one-shot script.** `backend/scripts/backfill_batch_identifier_mirrors.py`, idempotent via `ON CONFLICT DO NOTHING` on the workspace-unique constraint. Logs per-workspace `{created, skipped, malformed}`. Mirrors the existing `backfill_bemis_murcko.py` pattern.

```python
derived_from_molecule_identifier_id: uuid.UUID | None = None
```
The `create()` factory accepts it; existing callers pass nothing and get NULL.

### Repository round-trip

`BatchIdentifierModel` gains the column; `_to_model` / `_to_entity` round-trip it. No new query method — existing read paths return the FK transparently.

## Auto-sync rules

`SyncBatchIdentifierMirrors` is a thin collaborator (not a use case — no auth check, no UoW; it operates inside the caller's UoW). Two entry points:

```python
class SyncBatchIdentifierMirrors:
    """Generates and persists auto-mirror BatchIdentifiers. Stateless."""

    async def fan_out_for_new_identifier(
        self,
        *,
        workspace_id: uuid.UUID,
        identifier: MoleculeIdentifier,
        batches: list[Batch],
        actor: uuid.UUID,
    ) -> MirrorSummary: ...

    async def fan_out_for_new_batch(
        self,
        *,
        workspace_id: uuid.UUID,
        batch: Batch,
        identifiers: list[MoleculeIdentifier],
        actor: uuid.UUID,
    ) -> MirrorSummary: ...
```

`MirrorSummary` carries `{created: int, skipped: list[SkippedMirror]}` where `SkippedMirror = {batch_number: str, mirror_string: str, reason: Literal["already_mapped", "workspace_conflict", "malformed_batch_number"]}`.

### Per-pair algorithm

For each `(MoleculeIdentifier, Batch)`:
1. **Derive suffix.** `parts = batch.batch_number.value.rsplit("-", 1)`. If `len(parts) != 2` or `not parts[1].isdigit()`, record `malformed_batch_number` and continue.
2. **Compose mirror string.** `mirror = f"{identifier.identifier}-{parts[1]}"`.
3. **Check for collision on this batch.** If `batch.identifiers` already contains a row with this `identifier` string, record `already_mapped` and continue.
4. **Check workspace uniqueness.** Query `BatchIdentifierRepository.find_by_external_identifier(workspace_id, mirror)`. If found on a different batch, record `workspace_conflict` and continue. (The DB constraint would catch it on insert too; we pre-check to skip silently rather than abort the transaction.)
5. **Insert.** Create `BatchIdentifier` with the locked field values and append to `batch.identifiers`; the existing `BatchRepository.save(batch)` round-trip persists it.

### Performance

A molecule with 50 batches getting a new synonym → 50 mirror inserts. A new batch on a molecule with 50 synonyms → 50 mirror inserts. Both within one UoW; well under the existing CreateBatch latency budget. No concurrent fan-out needed.

## Trigger points

| Use case | New behavior |
|---|---|
| `AddIdentifier` (chemical_registration) | After `repo.save(mol)`, load all batches for the molecule, call `fan_out_for_new_identifier`. Return `mirror_summary` on the `Result.Success`. |
| `RemoveIdentifier` (chemical_registration) | **No code change.** DB cascade deletes the mirrors when the parent `molecule_identifiers` row is deleted. |
| `CreateBatch` (inventory) | After `repo.save(batch)`, call `fan_out_for_new_batch` with `mol.identifiers` (already loaded for the molecule check at line 91). Return `mirror_summary` on the `Result.Success`. |
| `EnsureBatchExists` (inventory) | On the create branch only, mirror the `CreateBatch` behavior. The existing alias insertion (the `external_identifier` that triggered the placeholder creation) is unrelated and continues unchanged with NULL FK. |
| `BulkAddBatchIdentifiers` | No change. Bulk imports always produce chemist-added rows (NULL FK). |
| `RegisterMolecule` | Already calls `mol.add_identifier(...)` directly (for name auto-promotion + explicit external_ids) before the first `repo.save(mol)`. At that point no batches exist for the molecule, so fan-out is a no-op. No code change needed — the first `CreateBatch` after registration picks up these synonyms via its own fan-out. |

## Response shape + FE wiring

### BE response

Both endpoints return the existing payload plus:
```jsonc
{
  // ...existing identifier or batch fields...
  "mirror_summary": {
    "created": 12,
    "skipped": [
      {"batch_number": "CC-036715-002", "mirror_string": "SACC-0036913-002", "reason": "workspace_conflict"}
    ]
  }
}
```
Backwards-compatible: existing FE callers that ignore the field continue to work; only new toast wiring reads it.

### FE wiring

- `useAddMoleculeIdentifier` / `useCreateBatch` hooks check `data.mirror_summary` on success.
- If `created > 0`: Sonner success toast `"{created} batch mirrors created"`.
- If `skipped.length > 0`: append `" · {skipped.length} skipped"` with a `Details` action that opens a small popover listing each skipped row.
- If `created === 0 && skipped.length === 0` (e.g. molecule with no batches yet): no toast.

The popover lists `{mirror_string} → already on {batch_number}` (workspace_conflict) or `{mirror_string} (already a manual identifier)` (already_mapped). Chemist gets the info and decides whether to act manually.

## Conflict semantics in detail

Three skip reasons map to three chemist mental models:

- **`already_mapped`** — a chemist already manually added a `BatchIdentifier` to *this batch* with the exact mirror string. Common case: someone added `SACC-0036913-002` manually before the molecule synonym was registered. The manual row is preserved (NULL FK). Auto-sync writes nothing.
- **`workspace_conflict`** — the mirror string exists on a *different batch* in the workspace. Workspace-unique constraint forbids inserting. Manual row preserved on its existing batch; auto-sync writes nothing on this batch. Chemist must reconcile manually (likely by removing the misplaced manual identifier on the other batch, then re-adding the molecule synonym).
- **`malformed_batch_number`** — the batch's number doesn't end in `-NNN` digits (EXTERNAL_REFERENCE placeholders, hypothetical legacy data). Skip silently; this is rare enough that the chemist sees it only if it actually surfaces.

Pre-checking (rather than letting the DB unique constraint fire) avoids partial-transaction aborts when a batch fan-out hits one conflict among many — without pre-check, we'd need savepoint-per-insert or transaction rollback handling. The pre-check costs N extra `find_by_external_identifier` queries per fan-out; acceptable given N ≤ ~50 in typical cases.

## Backfill

`backend/scripts/backfill_batch_identifier_mirrors.py`:

```python
# Pseudocode
for workspace in workspaces:
    for molecule in workspace.molecules:
        identifiers = molecule.identifiers  # already loaded with mol
        batches = batch_repo.find_by_molecule(workspace.id, molecule.id)
        for identifier in identifiers:
            for batch in batches:
                suffix = derive_suffix(batch.batch_number.value)
                if suffix is None:
                    log.malformed += 1
                    continue
                mirror_string = f"{identifier.identifier}-{suffix}"
                # INSERT ... ON CONFLICT (workspace_id, identifier) DO NOTHING
                inserted = await raw_insert(
                    workspace_id=workspace.id,
                    batch_id=batch.id,
                    identifier=mirror_string,
                    identifier_type="custom",
                    source="compound-syn (backfill)",
                    derived_from_molecule_identifier_id=identifier.id,
                    registered_by=identifier.registered_by,  # carry the original synonym's actor
                )
                if inserted:
                    log.created += 1
                else:
                    log.skipped += 1
    log_summary(workspace)
```

- Uses raw `INSERT ... ON CONFLICT DO NOTHING` rather than the use case path (no need for auth, UoW, dispatch).
- `registered_by` carries the original synonym's `registered_by` (preserves audit attribution to the chemist who created the synonym).
- `source = "compound-syn (backfill)"` distinguishes backfill rows from runtime rows; the FK is what code keys off, not the source string.
- Idempotent — second run = 0 new inserts (workspace-unique constraint catches everything).
- Batches by workspace; logs per-workspace summary; safe to ctrl-C and resume (each workspace is independent).
- For a ~50K-molecule workspace with mean ~1 synonym + ~1 batch per molecule, expect ~50K inserts. Run time ~minutes.

## Open caveats (intentional, not blockers)

- EXTERNAL_REFERENCE placeholder batches typically still have a well-formed `CC-XXXXXX-NNN` batch_number (per `EnsureBatchExists` using `next_batch_number`), so they participate in mirror fan-out normally. If an external system ever creates a placeholder via a non-standard path, the `malformed_batch_number` skip is the safety net.
- Mirrors are not retroactively created when a molecule synonym is added via a non-use-case path (e.g. a future bulk-import script). If/when a bulk molecule-identifier importer ships, it should call the same helper.
- The auto-mirror's `source = "compound-syn"` and the backfill's `source = "compound-syn (backfill)"` are observable to chemists in the Identifiers card. If they find the distinction noisy, normalize to a single label in a follow-up.
- Chemists CAN delete individual mirror rows from the batch Identifiers card via the existing `RemoveBatchIdentifier` use case. We do nothing to prevent this. The deleted mirror does not auto-regenerate — no trigger fires on row absence. If the chemist later removes + re-adds the parent molecule synonym, the fan-out re-creates the mirror naturally. The "manually deleted but parent synonym still present" state is intentional: chemists own their batch Identifiers card, even for auto-generated rows.
